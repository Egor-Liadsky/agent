## Why

Per-chat лимит контекста (`settings.max_context_tokens`) уже проходит через
оба репозитория, но сквозной путь ни разу не проверялся целиком, и сегодня
клиентская настройка бесполезна на сервисе без операторского
`AGENTD_MAX_CONTEXT_TOKENS`: `effective_context_limit` отвечает
`400 context_limit_invalid` на любое клиентское значение при незаданном
операторском (`agent-sever/src/app.rs:114`). Одновременно длинный чат сегодня
нечем спасти: `POST /v1/chat` с `chat_id` шлёт провайдеру всю сохранённую
историю, упирается в `400 context_limit_exceeded` и становится непригоден для
продолжения — остаётся завести новый чат и потерять контекст. Оба вопроса — об
управлении контекстом одного чата и трогают оба репозитория, поэтому решаются
одним изменением в общем экземпляре OpenSpec.

Это изменение поглощает незавершённый черновик
`agent-sever/openspec/changes/summarize-chat-history`: его каталог удаляется
первой задачей, чтобы не осталось двух изменений об одном и том же.

## What Changes

### Часть 1. Ревизия per-chat `max_context_tokens`

Сквозной путь пройден по коду; расхождения, найденные проверкой, входят в
область изменения (подробности и код с номерами строк — в `design.md`):

- **BREAKING** (для контракта ошибок, не для существующих развёртываний):
  клиентский лимит перестаёт требовать операторского. Эффективный лимит —
  минимум из заданных: заданы оба — клиентский (он не может превышать
  операторский, иначе `400 context_limit_invalid`), задан только клиентский —
  он и действует, задан только операторский — действует он, не задан ни один —
  лимит не проверяется. Сегодня последний из этих случаев для клиентского
  значения отвечает `400`.
- Лимит проверяется и при сохранении: `POST /v1/chats` и
  `PATCH /v1/chats/{id}` отклоняют `max_context_tokens` больше операторского
  тем же `400 context_limit_invalid`, а не принимают настройку, которая
  сорвёт каждый последующий `POST /v1/chat`. Сегодня
  `validate_settings_for_storage` лимит не смотрит вовсе, а для чатов с
  провайдером `ollama` выходит раньше любых проверок.
- Разница в поведении клиента фиксируется явно, а не остаётся случайной:
  `POST /v1/chat` поле при `None` опускает (сохранённый лимит чата остаётся),
  а `POST /v1/chats` и `PATCH /v1/chats/{id}` шлют его всегда, включая `null`
  (настройки чата задаются целиком экраном настроек TUI, и `null` снимает
  лимит). Обе ветки закрепляются тестами.
- Остальное проверено и работает: сохранение лимита в JSON `settings`
  колонки `chats.settings`, разбор `double_option` в `dto.rs` («ключа нет» /
  явный `null`), обратный разбор `settings` из `GET /v1/chats/{id}` в
  `ChatSettings` клиента и показ лимита в настройках чата TUI. Для этих веток
  добавляются тесты, закрепляющие текущее поведение.

### Часть 2. Суммаризация истории на сервисе

- Компактизация истории чата: последние `N` сообщений уходят провайдеру
  дословно, всё, что старше, заменяется одним текстом-пересказом. Сообщения в
  хранилище не меняются и не удаляются — `GET /v1/chats/{id}/messages`
  по-прежнему отдаёт полную переписку.
- Пересказ обновляется ступенчато: новый строится, когда за границей
  последних `N` накопилось не меньше шага (`AGENTD_SUMMARY_STEP_MESSAGES`,
  по умолчанию 10) ещё не пересказанных сообщений; между ступенями
  подставляется прежний пересказ без обращения к модели.
- Обновление ленивое: при сборке истории очередного `POST /v1/chat`, **до**
  проверки лимита контекста, чтобы компактизация спасала чат от
  `context_limit_exceeded`, а не срабатывала после отказа.
- Новые переменные окружения: `AGENTD_SUMMARY_ENABLED` (по умолчанию `false`
  — без настройки поведение сервиса не меняется), `AGENTD_SUMMARY_KEEP_MESSAGES`
  (`N`, по умолчанию 20), `AGENTD_SUMMARY_STEP_MESSAGES` (10),
  `AGENTD_SUMMARY_MODEL`, `AGENTD_SUMMARY_MAX_CHARS`. Разбор и валидация — по
  образцу `AGENTD_MAX_CONTEXT_TOKENS`: нечисловое и нулевое значение —
  фатальная ошибка при старте.
- Хранение: пересказ в отдельной таблице `chat_summaries`, миграция
  `migrations/0002_chat_summaries.sql`.
- Наблюдаемость: `GET /v1/chats/{id}` и `GET /v1/chats` отдают поля только для
  чтения `summary` и `summary_through_seq`, а ответ `POST /v1/chat`
  дополняется блоком `context` (сколько сообщений заменено пересказом,
  строился ли пересказ на этом запросе) — иначе настройки не с чем сравнивать.
- Ошибка вызова модели ради пересказа не роняет пользовательский запрос:
  `WARN`, прежний пересказ (или полная история, если пересказа нет), проверка
  лимита как обычно.
- `POST /v1/chat` без `chat_id` компактизации не подлежит: хранилища у него
  нет, историю целиком присылает клиент.

### Часть 3. Настройка суммаризации с клиента

- `settings` пополняется полями `summary_enabled`, `summary_keep_messages`,
  `summary_step_messages`: в `POST /v1/chats` и `PATCH /v1/chats/{id}` они
  сохраняются в настройках чата, в `POST /v1/chat` действуют разовым
  переопределением. Семантика «поля нет / поле `null`» — ровно та же, что у
  `max_context_tokens` после части 1, второго набора правил не заводится.
- Операторские значения — умолчания и границы: `AGENTD_SUMMARY_ENABLED` —
  только умолчание для новых чатов (чат может включить компактизацию на
  сервисе, где она выключена по умолчанию), `AGENTD_SUMMARY_KEEP_MESSAGES` —
  потолок дословного хвоста, `AGENTD_SUMMARY_STEP_MESSAGES` — нижняя граница
  шага. Нарушение границ — `400 summary_settings_invalid`. Модель пересказа
  остаётся операторской и клиенту не передаётся.
- `agent-cli`: поля `summary_*` в `agentcore::ChatSettings` как `Option`,
  умолчания для новых чатов в конфиге и показ в `config show`, отправка из
  `agentclient` в обоих payload, правка в том же экране настроек чата TUI, где
  правится лимит контекста — чтобы на одном чате сравнивать разные `N` и шаг.

## Capabilities

### New Capabilities

- `chat-context-limit`: лимит контекстного окна чата — сохранение в настройках
  чата, разовое переопределение на запрос, соотношение клиентского и
  операторского значений, проверка при сохранении и при вызове, поведение
  клиента при отправке поля.
- `context-summary`: компактизация истории чата — дословный хвост из
  последних `N` сообщений, ступенчатое построение и отдельное хранение
  пересказа, подстановка пересказа вместо вытесненной части, порядок
  «сначала компактизация, потом проверка лимита», настройка компактизации на
  уровне чата поверх операторских умолчаний, устойчивость к ошибке построения
  и наблюдаемость.

### Modified Capabilities

Нет: в `openspec/specs/` обоих подмодулей и зонтичного репозитория пока нет
заархивированных спек — требования о лимите контекста живут в незавершённых
изменениях `agent-sever` (`limit-context-window`,
`persist-chat-context-limit`). Их требования не переопределяются, а
пересобираются в `chat-context-limit` этого изменения с учётом ревизии.

## Impact

### `agent-cli`

- `crates/core/src/config.rs`: поля `summary_enabled`,
  `summary_keep_messages`, `summary_step_messages` в `ChatSettings` и
  умолчания для новых чатов в `Config` + `default_chat_settings`.
- `crates/client/src/lib.rs` и `crates/client/src/chats.rs`: передача полей
  `summary_*` в payload `POST /v1/chat` и `ChatSettingsUpdate`; закрепление
  семантики `max_context_tokens` в обоих payload.
- `crates/cli/src/main.rs`: умолчания `summary_*` в `config show` и командах
  настройки.
- `crates/cli/src/tui.rs`: поля `summary_*` в экране настроек чата рядом с
  лимитом контекста (правки точечные — файл ~2100 строк).
- `crates/client/src/tests.rs`, `crates/client/src/chats/tests.rs`,
  `crates/core/src/config.rs` (тесты) — покрытие новых полей и закрепление
  поведения лимита.
- README `agent-cli`: поля настроек чата, команды конфига, горячие клавиши
  экрана настроек.
- Требуется пуш `agent-cli` в `main`: сервис читает `summary_*` из
  `agentcore::ChatSettings`.

### `agent-sever`

- `src/config.rs`: пять переменных `AGENTD_SUMMARY_*`.
- `src/app.rs`: `effective_context_limit` (клиентский лимит без
  операторского), проверка лимита и настроек компактизации при сохранении
  (`validate_settings_for_storage`), сборка компактизованной истории и вызов
  модели ради пересказа до `check_context_limit`.
- `src/store.rs` + `migrations/0002_chat_summaries.sql`: чтение и запись
  пересказа.
- `src/dto.rs`: поля `summary_*` во входном DTO настроек (через
  `double_option`), `summary`/`summary_through_seq` в ответе о чате, блок
  `context` в ответе `POST /v1/chat`.
- `src/error.rs`: код `summary_settings_invalid`.
- `src/tests.rs`: тесты через `wiremock`, включая вызов модели ради пересказа.
- README `agent-sever`: переменные окружения, поля `settings`, новые поля
  ответов, поведение компактизации.
- Требуется обновление `Cargo.lock` в `agent-sever`: после пуша `agent-cli`
  снять локальный `[patch]`, выполнить `cargo generate-lockfile` и прогнать
  `cargo test --locked`.

### Прочее

- Удаляется каталог `agent-sever/openspec/changes/summarize-chat-history`
  (поглощённый черновик).
- Эксплуатация: на ступенях пересказа заметно растёт число вызовов провайдера.
