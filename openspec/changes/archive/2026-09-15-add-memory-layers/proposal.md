## Why

Сервис уже умеет по-разному урезать историю диалога (`summary`,
`sliding_window`, `facts`, `branching`), но все четыре стратегии работают с
одним и тем же — сообщениями чата — и ничего не переживает сам чат. Нет
места для данных задачи, которая решается прямо сейчас (черновые параметры,
промежуточные договорённости), и нет места для того, что должно быть видно
владельцу в следующем чате (профиль, принятые решения, извлечённые знания).
Нужна стратегия `memory_layers`, которая явно разводит три слоя памяти по
разной области жизни и делает решение о том, что и куда попало, видимым в
ответе, а не побочным эффектом обновления контекста. Изменение затрагивает
оба репозитория (новое значение `ContextStrategy` и поля `ChatSettings` в
`agent-cli`, реализация стратегии, хранилище и HTTP в `agent-sever`, экран
памяти в TUI), поэтому заводится здесь, а не в одном из репозиториев.

## What Changes

- Новая стратегия контекста `memory_layers` в `agentcore::config::ContextStrategy`
  (пятое значение перечисления, `agent-cli`) и её реализация
  `ContextStrategyImpl` в новом модуле `agent-sever/src/memory.rs`.
- Три слоя памяти с раздельным хранением (`agent-sever`):
  - краткосрочная — существующая таблица `messages`, без новой схемы;
  - рабочая — новая таблица `chat_working_memory` (слоты «ключ-значение» в
    рамках активной задачи чата, живут до её завершения или смены);
  - долговременная — новая таблица `owner_long_term_memory` (профиль,
    решения, знания в области видимости владельца, переживают чат).
- Автоматический маршрутизатор записей: дешёвый вызов модели после каждого
  сообщения пользователя возвращает JSON-список операций с явным слоем,
  действием, ключом/типом, значением и причиной; операции валидируются перед
  применением, отказ маршрутизатора не блокирует основной ответ.
- Ручные HTTP-эндпоинты чтения, записи и удаления записей рабочей и
  долговременной памяти, с приоритетом ручной операции над автоматической при
  конфликте на одном ключе в одном такте обработки запроса.
- Разбивка по слоям в блоке `context` ответа `POST /v1/chat`: сколько записей
  каждого слоя подставлено, сколько символов ушло, сколько операций
  маршрутизатора применено и отброшено.
- Переменные окружения `AGENTD_MEMORY_*` (`agent-sever`) для операторских
  умолчаний, дублирующие поля в `ChatSettings` (`agent-cli`) для
  переопределения на чат.
- Экран памяти в `agentcli` (TUI, `agent-cli`): просмотр по слоям, ручное
  добавление/правка/удаление записей рабочей и долговременной памяти, выбор
  стратегии `memory_layers` и её параметров без пересоздания чата, показ
  разбивки по слоям после ответа.

## Capabilities

### New Capabilities
- `memory-layers`: три слоя памяти агента (краткосрочный, рабочий,
  долговременный), маршрутизация записей по слоям, стратегия контекста
  `memory_layers`, наблюдаемость через блок `context`, ручное управление через
  HTTP и TUI.

### Modified Capabilities
(нет — существующие стратегии `summary`, `sliding_window`, `facts`,
`branching` и их поведение не меняются; `memory_layers` добавляется как
самостоятельная стратегия рядом с ними, ветвление по стратегии в
`agent-sever/src/context.rs` расширяется одной веткой `match`, что не меняет
требований к уже существующим стратегиям)

## Impact

### agent-cli

- `crates/core/src/config.rs`: пятое значение `ContextStrategy` —
  `MemoryLayers`; новые поля `ChatSettings` (`memory_router_enabled`,
  `memory_short_term_tail`, `memory_working_max_entries`,
  `memory_long_term_max_entries`).
- `crates/cli/src/tui.rs`: выбор стратегии `memory_layers` и её параметров
  без пересоздания чата, экран памяти по трём слоям, ручное
  добавление/правка/удаление записей, отображение разбивки по слоям из
  блока `context`.
- `README.md`: новая стратегия, поля настроек, горячие клавиши и экран TUI.
- Пуш в `main` требуется: `agent-sever` использует новое значение
  `ContextStrategy` и новые поля `ChatSettings` из `agentcore`.

### agent-sever

- `src/memory.rs` (новый): реализация `ContextStrategyImpl` для
  `memory_layers`, маршрутизатор операций, сборка разделов системного
  сообщения.
- `src/context.rs`: одна веткa `match` на новую стратегию, без условий по
  слоям в `handle_chat_in_existing`.
- `src/store.rs`: таблицы `chat_working_memory`, `owner_long_term_memory`,
  колонка `active_task_id` у `chats`, функции доступа.
- `src/dto.rs`: разбивка по слоям в `ContextDto`, DTO эндпоинтов памяти.
- `src/app.rs`: маршруты чтения/записи/удаления записей памяти.
- `src/config.rs`: переменные `AGENTD_MEMORY_*`.
- `migrations/0004_memory_layers.sql` (новый).
- `src/tests.rs`: тесты маршрутизации, валидации, стратегии, эндпоинтов.
- `README.md`: новая стратегия, эндпоинты, переменные окружения.
- После пуша `agent-cli` в `main`: временно убрать `[patch]` в
  `.cargo/config.toml`, выполнить `cargo generate-lockfile`, проверить
  `grep -A2 'name = "agentcore"' Cargo.lock` (коммит, не путь), прогнать
  `cargo test --locked`, вернуть `[patch]` для локальной разработки.
