## 1. Что это за проект

Система личного финансового учёта: Python 3.12, FastAPI, aiogram (Telegram-бот), SQLAlchemy 2.x,
Alembic, PostgreSQL (с RLS), Redis, APScheduler, SPA-фронтенд (React). Запуск и зависимости — через `uv`,
тесты — pytest в `tests/`. Документация: `README.md`, `docs/architecture.md`, `docs/bot-guide.md`,
`docs/dev-log.md`, план этапа — `docs/tasks/2026-09-23-stage1-plan.md`.

## 2. Использование

### 2.1 Быстрый старт

- `make up` поднимает `postgres`, `redis`, одноразовый сервис `migrate` (README.md:92, 96).
- Отдельно гонять миграции после `make up` не нужно: цель сама запускает `alembic upgrade head` (README.md:99).
- Для запуска процессов вне Docker, через `uv run`, оба хоста в конфиге заменяются на `localhost` (.env.example:12).
- `make up` в `docs/architecture.md:3145` описан как «Поднять стек локально».

### 2.2 Make-цели

| Цель | Назначение |
| --- | --- |
| `make up` | Поднять стек локально (postgres, redis, migrate) |
| `make test` | `uv run pytest` |
| `make lint` | `ruff check`, `ruff format --check`, `mypy src` |
| `make revision m="..."` | Создать миграцию Alembic |
| `make migrate` | Применить миграции |
| `make seed`, `make recalc` | Есть в Makefile (на момент сбора — заглушки более поздних этапов) |

(README.md:115-122)

### 2.3 Проверки и CI

- Перед коммитом: `make test` и `make lint` (CLAUDE.md:75-76).
- CI (`.github/workflows/ci.yml`): `uv run ruff check` (:31), `uv run mypy src` (:35),
  `uv run pytest -m "not integration"` (:52), `uv run pytest -m integration` (:76).

### 2.4 Команды бота

| Команда | Действие |
| --- | --- |
| `/start` | Регистрация или привязка, онбординг: базовая валюта, таймзона, первый счёт |
| `/menu` | Меню |
| `/add` | Диалог добавления операции с выбором типа |
| `/expense`, `/income` | Сразу в нужный диалог |
| `/transfer` | Перевод между счетами |
| `/balance` | Остатки по всем счетам и итог в базовой валюте |
| `/today`, `/month` | Сводка расходов и доходов за день или текущий месяц |
| `/goals` | Список целей с прогрессом |
| `/recurring` | Регулярные операции, включение и выключение |
| `/undo` | Сторнировать последнюю операцию, введённую в боте |
| `/cancel` | Выйти из любого диалога |
| `/help` | Справка, в том числе синтаксис быстрого ввода |

(docs/architecture.md:1832-1846)

### 2.5 Быстрый ввод одной строкой

- Раздел «6.5 Быстрый ввод одной строкой» (docs/architecture.md:2085) и раздел 5 в `docs/bot-guide.md` (:97).
- Реализация: `quick.router` — текст без `/` в `StateFilter(None, QuickConfirm)`, callback-префикс `qk:`;
  свободная строка превращается в карточку подтверждения (docs/architecture.md:1870).
- Валюту в диалогах `/expense` и `/income` выбрать нельзя — для этого используется быстрый ввод
  (docs/bot-guide.md:94). В диалогах нет и выбора даты (docs/bot-guide.md:218).
- Ручная проверка корректности остатков: значения в `/balance` должны совпадать с эталонным запросом
  (docs/bot-guide.md:228).

- Допущение по запросу: «использование» растолковано как быстрый старт, make-цели, проверки и команды
  бота; имя файла `finplan-usage-and-history.md` выбрано составителем.

  заглушками более поздних этапов — это состояние плана, а не подтверждение готовой функциональности.
- В сводку сознательно не включены содержимое `.env`, строки подключения, ключи и токены:
  конфигурация проекта читается из окружения, а секреты в отчёт не выносятся.
- Команда пересоздания локального docker-тома в отчёт не вынесена как готовая к выполнению:
  она уничтожает локальные данные и требует явного подтверждения перед запуском.
